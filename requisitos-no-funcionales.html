Requisitos no funcionales

Los requisitos no funcionales establecen condiciones medibles sobre seguridad, privacidad, accesibilidad, rendimiento, compatibilidad, disponibilidad y fiabilidad. No se presentan como nuevas funciones de usuario.

Código Condición Criterio de comprobación
RNF01 Seguridad de contraseñas. El sistema deberá almacenar las contraseñas con una función de hash adaptativa y una sal única por cuenta. Una inspección de la base de datos confirma que no hay contraseñas en texto plano.
RNF02 Comunicaciones seguras. El sistema deberá proteger las comunicaciones entre la web, la aplicación Android y el servidor mediante TLS 1.2 o superior. Las conexiones HTTP se redirigen a HTTPS y la negociación TLS no acepta versiones inferiores a 1.2.
RNF03 Control de acceso. El servidor deberá rechazar las operaciones de los usuarios cuyo rol no tenga autorización para realizarlas. Las pruebas de acceso con roles no autorizados reciben una respuesta de denegación.
RNF04 Privacidad de la ubicación. El sistema deberá mantener privados por defecto los recorridos y la ubicación del corredor fuera de los enlaces temporales autorizados. Un usuario diferente no puede consultar ubicaciones ni entrenamientos sin autorización vigente.
RNF05 Facilidad de aprendizaje. La aplicación web deberá permitir que un corredor que inicia sesión por primera vez planifique una ruta en tres minutos o menos sin ayuda. En una prueba con usuarios nuevos, los participantes completan la tarea sin asistencia dentro de tres minutos.
RNF06 Accesibilidad web. La aplicación web deberá cumplir las pautas WCAG 2.1 de nivel AA en las pantallas incluidas en el prototipo. La revisión de accesibilidad y las pruebas de teclado no detectan incumplimientos del nivel AA en las pantallas evaluadas.
RNF07 Rendimiento de las rutas. El servidor deberá responder las consultas de recomendación y cálculo de rutas en cinco segundos o menos para al menos el 95 % de las solicitudes con 50 usuarios concurrentes. Una prueba de carga documenta por separado el tiempo de respuesta de ambas operaciones.
RNF08 Compatibilidad web. La aplicación web deberá funcionar en las dos últimas versiones de Chrome, Firefox, Edge y Safari, en anchos de pantalla de 360 a 1920 píxeles. Se ejecuta la misma prueba de navegación y planificación en los navegadores y tamaños indicados.
RNF09 Compatibilidad Android. La aplicación móvil deberá poder instalarse y ejecutarse en dispositivos con Android 10 o superior. Se instala el APK y se comprueba el inicio y la grabación en un dispositivo Android compatible.
RNF10 Disponibilidad del prototipo. La aplicación web y su API deberán mantenerse accesibles al menos el 95 % del tiempo durante la prueba piloto, excluyendo mantenimientos comunicados con al menos 24 horas de anticipación. Un registro de disponibilidad del período piloto permite calcular el porcentaje de tiempo accesible.
RNF11 Conservación del recorrido. La aplicación Android deberá conservar localmente los puntos GPS ya capturados cuando se interrumpa la conexión a internet. Se registra un entrenamiento sin red, se restablece la conexión y se comprueba que los puntos guardados sigan disponibles.
RNF12 Advertencia del índice. El sistema deberá identificar siempre el índice de seguridad como referencial y señalar cuando un tramo no tenga información suficiente para evaluarlo. Ninguna consulta muestra una garantía de seguridad y un tramo sin datos presenta una advertencia visible.
