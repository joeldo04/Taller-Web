01 / CONCEPTOS BÁSICOS

Dos herramientas que trabajan juntas

Sus nombres se parecen, pero no son lo mismo. Esta es la diferencia:

G
HERRAMIENTA LOCAL

¿Qué es Git?

Git es un sistema de control de versiones que registra los cambios de los archivos de un proyecto. Nos ayuda a revisar el historial y recuperar versiones anteriores.

✓ Puede funcionar sin internet.

GH
PLATAFORMA EN LÍNEA

¿Qué es GitHub?

GitHub es una plataforma que permite alojar repositorios Git, compartir código y colaborar con otros desarrolladores. Sus repositorios pueden ser públicos o privados.

✓ Facilita el trabajo en equipo.

!

En pocas palabras: Git registra los cambios de nuestro código; GitHub nos permite compartir el repositorio y colaborar por internet.

02 / CAJA DE HERRAMIENTAS

Comandos básicos de Git

Estos son los comandos principales que podemos usar durante nuestro taller.

Comando¿Para qué sirve?
git --versionComprueba qué versión de Git está instalada.
git initInicia un repositorio Git en una carpeta.
git statusMuestra los archivos modificados y el estado del repositorio.
git add .Prepara los cambios para el siguiente commit.
git commit -m "Avance"Registra en Git los cambios preparados.
git logMuestra el historial de commits.
git branchLista las ramas locales del proyecto.
git switch -c mi-ramaCrea una rama nueva y cambia a ella.
git clone URLDescarga una copia de un repositorio existente.
git pushEnvía commits al repositorio remoto.
git pullObtiene e integra cambios del repositorio remoto.

Recuerda: guardar con Ctrl + S no crea un commit. Para registrar una versión usamos git add y git commit.

03 / VOCABULARIO

Palabras importantes del taller

Conceptos que debemos saber explicar en clase.

01

Repositorio

Proyecto con sus archivos y el historial de cambios que guarda Git.

02

Commit

Registro de una versión de los cambios preparados.

03

Branch (rama)

Línea de trabajo que permite desarrollar cambios por separado.

04

README.md

Documento que explica el proyecto, sus herramientas y cómo revisarlo.

05

.gitignore

Archivo que indica qué archivos no rastreados debe ignorar Git.

06

Pull Request

Propuesta para revisar e integrar los cambios de una rama en otra.

04 / PRÁCTICA GRUPAL

¿Cómo trabajamos en el repositorio?

Ejemplo con una rama propia, como web-completo.

1

Clonamos el repositorio

Cada integrante descarga el proyecto del equipo una sola vez con git clone URL.

2

Creamos una rama

Para trabajar sin cambiar directamente main, usamos git switch -c web-completo.

3

Guardamos nuestros avances

Preparamos los cambios con git add . y registramos un commit con git commit.

4

Compartimos y revisamos

Subimos la rama con git push -u origin web-completo y podemos crear un Pull Request hacia main.

Antes de comenzar un nuevo avance, revisen el estado de su repositorio con git status. Coordinen qué archivos editará cada integrante para evitar conflictos de cambios.
